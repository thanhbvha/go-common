# v2 API and adoption guide

The module is `github.com/thanhbvha/go-common/v2`. This is a single Go module with
independent packages and optional Foundation composition. v1 compatibility shims are
not maintained. Upgrade imports, update bootstrap ownership, and compile the complete
application before adoption. The repository does not publish a release automatically.

| Area | v2 contract |
|---|---|
| Logging | Synchronous by default; `Logger()` and `With(...)` expose native slog loggers. Only the root runtime owns `Shutdown(ctx)`; async queue/overflow are explicit. |
| Telemetry | `New(ctx,cfg)` is local; `InstallGlobal()` is explicit. Sampling zero means zero root samples; TLS and no baggage are defaults. |
| Configuration | File/env overlay preserves initialized defaults, binds tagged fields absent from files, validates before publication; `Watch` owns a cancellable watcher. |
| Health | SQL/Redis checkers move to integration subpackages. Each callback has one execution in flight. |
| HTTP errors | Public 4xx messages are separate from internal causes; all 5xx and unknown errors are masked. |
| Validator | Use immutable `validator.New(rules)` instances and checked validation; no mutable global registration. |
| Auth | Use options-based managers and explicit key IDs/claim policy. Refresh sessions use the atomic session store; the per-user verify-then-set API is removed. Revocation dependency failures are identifiable with `ErrAuthBackendUnavailable` and HTTP middleware returns a masked 503. |
| HTTP client | `NewClient` returns an error and accepts only a pure HTTP(S) origin/base path. Retry is method/body aware; unsafe-method retries require explicit idempotency opt-in. Resty remains the request engine. |
| Rate limit | Checked UniversalClient constructor; explicit middleware failure policy; whole millisecond windows. |
| Cache | Namespace required for Redis cache. No database flush in Cache. `NewRedisLock` returns `(*RedisLock, error)` so entropy failure is recoverable; lock ownership and positive millisecond TTLs are enforced. |
| Redis/NATS/Kafka | Health observations do not own lifecycle. Close is terminal, cancellation is honored; NATS `Drain(ctx)` waits for completion. |
| Cron | Core accepts a narrow lease provider. Redis lease integration lives in `cron/lease/redis`; no Redis/cache dependency for local schedules. |
| Migrations | An instance-owned Goose Provider, context-aware operations and structured status. Borrowed DB pools remain caller-owned. Run migrations as a dedicated deployment job. |
| gRPC errors | Explicit server/transport statuses are rebuilt with generic messages and no private details; selected client-error statuses remain public contracts. |
| Kafka consumption | Each convenience subscription owns a bounded manual consumer, commits successful work synchronously, and stops on handler/commit/poll error. Advanced offset control uses native factory APIs. |
| WebSocket | Validate production policy before bootstrap; provide an explicit authorizer and authenticated principal. Tenant routing uses tenant-scoped APIs, and client error envelopes require an explicit public code/message policy. |

Delivery remains at-least-once where documented. Dedupe, leases and commit acknowledgements
do not make application side effects exactly-once. Use transactional business keys,
outbox/inbox recipes and bounded retries. See [outbox guidance](../db/OUTBOX.md).
